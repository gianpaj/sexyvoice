Use the API when you want to generate speech from your own backend or app.

## Prerequisites

- A SexyVoice account
- API key from **Dashboard → API Keys**
- A one-time purchase or subscription payment to unlock API keys, plus enough credits to generate speech

## 1. Authenticate

Set `SEXYVOICE_API_KEY` in your local shell or server environment. Send it as a
Bearer token when listing voices, generating speech, or checking billing:

```bash
curl 'https://sexyvoice.ai/api/v1/voices' \
  -H "Authorization: Bearer ${SEXYVOICE_API_KEY}"
```

The response has a `data` array. Pick a voice's `id` or its `name` and `model`
from the list. The catalog contains public text-to-speech voices, not your
private or cloned voices.

## 2. Generate Speech

You can select a voice in either of two ways:

- Pass `voice` + `model` for name-based lookup.
- Pass `voiceId` from `GET /api/v1/voices`; the API derives the model from that voice ID.

### Using `gpro` model

Gemini voices (`gpro`, `gpro31`, and `gpro38`) accept an optional `temperature` (range `0`–`2`).
Higher values make the delivery more varied and expressive; omit it to use the model
default. `temperature` is ignored for non-Gemini voices.

```bash
curl -X POST 'https://sexyvoice.ai/api/v1/speech' \
  -H "Authorization: Bearer ${SEXYVOICE_API_KEY}" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "gpro",
    "voice": "achernar",
    "input": "Hello from SexyVoice API",
    "style": "calm",
    "seed": 1234,
    "temperature": 1.2
  }'
```

### Using Gemini 3.8 Flash TTS

Select a voice returned by `/api/v1/voices` with `model: "gpro38"`.
Send spoken words in `input` and delivery instructions in `style`.
The API sends style as speech metadata, separate from the transcript.
Use inline tags such as `<sigh>` or `<short pause>` for brief vocal events.

Gemini 3.8 returns WAV audio and reports `gemini-3.8-flash-tts` in `usage.model`.
Requests do not fall back to Gemini 2.5 because extended voice IDs require 3.8.
Existing voice IDs and the `gpro` and `gpro31` models keep their behavior.

### Using G31 (Gemini 3.1 Flash TTS)

Gemini 3.1 supports inline audio expression tags like `[cheerfully]`,
`[whispering]`, and `[pause]`. Choose a voice listed as `gpro31` to use Gemini
3.1, or `gpro` to use Gemini 2.5 Pro. Both can fall back to Gemini 2.5 Flash
if the initial provider call fails. Check `usage.model` for the model that
actually generated the audio.

```bash
curl -X POST 'https://sexyvoice.ai/api/v1/speech' \
  -H "Authorization: Bearer ${SEXYVOICE_API_KEY}" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "gpro31",
    "voice": "achernar",
    "input": "[cheerfully] Hello from Gemini 3.1! [pause] This supports 70+ languages.",
    "seed": 1234
  }'
```

### Using a `voiceId`

Use `voiceId` when you want a stable identifier or when the same voice name
exists for more than one model. Replace `VOICE_ID_FROM_CATALOG` below with
the `id` you got from `GET /api/v1/voices`. Do not include `voice` or
`model` in the same request.

```bash
curl -X POST 'https://sexyvoice.ai/api/v1/speech' \
  -H "Authorization: Bearer ${SEXYVOICE_API_KEY}" \
  -H 'Content-Type: application/json' \
  -d '{
    "voiceId": "VOICE_ID_FROM_CATALOG",
    "input": "Hello from a voice ID",
    "style": "calm"
  }'
```

### Using Grok (xAI)

Grok voices support both MP3 (default) and WAV output via `response_format`. They also
accept an optional `speed` multiplier (range `0.7`–`1.5`, per the xAI TTS API) to slow
down or speed up delivery; omit it for the provider default. `speed` is ignored for
non-Grok voices.

```bash
curl -X POST 'https://sexyvoice.ai/api/v1/speech' \
  -H "Authorization: Bearer ${SEXYVOICE_API_KEY}" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "xai",
    "voice": "eve",
    "input": "Hello from Grok! [laugh] This is exciting.",
    "response_format": "mp3",
    "speed": 1.2
  }'
```

Each successful request generates fresh audio and returns HTTP `200` with
JSON, not audio bytes. Download the audio separately from `url`.

- `credits_used`: Credits charged for this request.
- `credits_remaining`: Account credit balance after generation.
- `usage.input_characters`: Length of the text sent to the provider. It
  includes the style text and prompt formatting for `gpro` and `gpro31`,
  but excludes separate style metadata for `gpro38`.
- `usage.model`: The model that generated the audio. This can be a provider
  model ID rather than the model alias you sent.

### Speech Limits

| Model                               | Maximum input on paid accounts | Allowed output     |
| ----------------------------------- | ------------------------------ | ------------------ |
| Gemini (`gpro`, `gpro31`, `gpro38`) | 1,000 characters               | WAV                |
| Grok (`xai`)                        | 1,000 characters               | MP3 (default), WAV |
| Orpheus (`orpheus`)                 | 500 characters                 | MP3                |

Accounts without a purchase or credit top-up have a 500-character effective
limit for all models. The API counts inline tags and Gemini style
instructions toward the limit, including any formatting added to the
`gpro` or `gpro31` prompt. For `gpro38`, the combined length of `input`
and `style` is checked even though they are sent separately. An empty
`input` or an `input` longer than 1,000 characters fails request validation.

## 3. Check credit balance

The API uses the same credit balance as your dashboard.

```bash
curl -X GET 'https://sexyvoice.ai/api/v1/billing' \
  -H "Authorization: Bearer ${SEXYVOICE_API_KEY}"
```

Response includes:

- `creditsLeft`
- `lastUpdated`
- `userId`
- `lastBillingTransaction`

## 4. Handle Errors + Debugging

- Log the `request-id` header from authenticated API endpoints when present.
- On failures, inspect `error.code` and `error.type`. See [Error Codes](../api-reference/error-codes).
- Authenticated endpoints share a [rate limit](../api-reference/api#rate-limits-and-request-ids) per key.
