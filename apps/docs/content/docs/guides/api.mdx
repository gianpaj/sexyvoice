Use the API when you want to generate speech from your own backend or app.

## Prerequisites

- A SexyVoice account
- API key from **Dashboard -> API Keys**
- A top-up or subscription payment to unlock API keys, plus enough credits to generate speech

## 1. Authenticate

Send your API key as a Bearer token:

```bash
-H 'Authorization: Bearer sk_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx'
```

## 2. Generate Speech

You can select a voice in either of two ways:

- Pass `voice` + `model` for name-based lookup.
- Pass `voiceId` from `GET /api/v1/voices`; the API derives the model from that voice ID.

### Using Gemini 3.8 Flash TTS

Gemini voices (`gpro38`) accept an optional `temperature` (range `0`–`2`).
Higher values make the delivery more varied and expressive; omit it to use the model
default. `temperature` is ignored for non-Gemini voices.

```bash
curl -X POST 'https://sexyvoice.ai/api/v1/speech' \
  -H 'Authorization: Bearer sk_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "gpro38",
    "voice": "achernar",
    "input": "Hello from SexyVoice API",
    "style": "calm",
    "seed": 1234,
    "temperature": 1.2
  }'
```

Select a voice returned by `/api/v1/voices` with `model: "gpro38"`.
Send spoken words in `input` and delivery instructions in `style`.
The API sends style as speech metadata, separate from the transcript.
Use inline tags such as `<sigh>` or `<short pause>` for brief vocal events.

Gemini 3.8 returns WAV audio and reports `gemini-3.8-flash-tts` in `usage.model`.
The supported model aliases are `gpro38`, `xai`, and `orpheus`.
Retired `gpro` and `gpro31` aliases return `400`; their voice IDs return `404`.
Choose a supported voice from `/api/v1/voices` before generating. Audio already
generated with retired voices remains available in your history.

### Using a `voiceId`

Use `voiceId` when you want a stable identifier from `GET /api/v1/voices` or when the same voice name exists for more than one model. Do not include `voice` or `model` in the same request.

```bash
curl -X POST 'https://sexyvoice.ai/api/v1/speech' \
  -H 'Authorization: Bearer sk_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx' \
  -H 'Content-Type: application/json' \
  -d '{
    "voiceId": "1236ed64-eedc-4608-91b8-d545966b3777",
    "input": "Hello from a voice ID",
    "style": "calm"
  }'
```

### Using Grok (xAI)

Grok voices support both MP3 (default) and WAV output via `response_format`. They also
accept an optional `speed` multiplier (range `0.7`–`1.5`, per the xAI TTS API) to slow
down or speed up delivery; omit it for the default `1.0`. `speed` is ignored for
non-Grok voices.

```bash
curl -X POST 'https://sexyvoice.ai/api/v1/speech' \
  -H 'Authorization: Bearer sk_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "xai",
    "voice": "eve",
    "input": "Hello from Grok! [laugh] This is exciting.",
    "response_format": "mp3",
    "speed": 1.2
  }'
```

Successful response includes:

- `url`: generated audio URL
- `credits_used`
- `credits_remaining`
- `usage`

## 3. Check credit balance

The API uses the same credit balance as your dashboard.

```bash
curl -X GET 'https://sexyvoice.ai/api/v1/billing' \
  -H 'Authorization: Bearer sk_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx'
```

Response includes:

- `creditsLeft`
- `lastUpdated`
- `userId`
- `lastBillingTransaction`

## 4. Handle Errors + Debugging

- Every response includes a `request-id` header. Log it in your app.
- On failures, inspect `error.code` and `error.type`.
- See [Error Codes](/api-reference/error-codes) for the full list.

## Useful Endpoints

- `POST /api/v1/speech`
- `GET /api/v1/billing`
- `GET /api/v1/voices`
- `GET /api/v1/models`
- `GET /api/v1/openapi`
