## Base URL

Use `https://sexyvoice.ai` as the API host.

## Authentication

Create an API key under **Dashboard → API Keys**, then send it as
`Authorization: Bearer YOUR_API_KEY`. Creating keys requires a previous
subscription payment or one-time credit purchase. Set `SEXYVOICE_API_KEY` in
your local shell or server environment to run the examples. Do not put your
key in browser code.

[GET /api/v1/openapi](./endpoints/openapi) is public and does not require a key.

In your profile, choose **Delete account or content** under **Danger Zone**,
then choose **Delete content**. This revokes your API keys. Create new keys to
use the API again. We keep usage records for billing and internal cost tracking.

```bash
curl -X GET 'https://sexyvoice.ai/api/v1/models' \
  -H "Authorization: Bearer ${SEXYVOICE_API_KEY}"
```

## Rate Limits and Request IDs

Speech, voices, models, and billing share a limit of **60 requests per minute
per API key**, with a burst capacity of 60. Requests with a valid key count
toward the limit before endpoint validation, so a failed request can still
consume a request. The public OpenAPI endpoint does not use this limit.

These four endpoints return the following headers on success and on handled
errors:

| Header                           | Meaning                                                        |
| -------------------------------- | -------------------------------------------------------------- |
| `request-id`                     | Support and debugging ID: `req_sv_` followed by 32 hex digits. |
| `X-RateLimit-Limit-Requests`     | Request allowance.                                             |
| `X-RateLimit-Remaining-Requests` | Requests remaining in the shared allowance.                    |
| `X-RateLimit-Reset-Requests`     | Reset time as an ISO 8601 timestamp.                           |

On a `401`, the rate-limit headers contain defaults, not your key's quota.
On a `429` with `rate_limit_exceeded`, wait until the reset time before
retrying. A `429` with `provider_quota_exceeded` instead means the upstream
provider is out of quota and the reset header does not predict its recovery.

## Endpoints

| Endpoint                                              | Returns                                                        |
| ----------------------------------------------------- | -------------------------------------------------------------- |
| [POST /api/v1/speech](./endpoints/api/v1/speech/post) | JSON with an audio URL, credits, and usage.                    |
| [GET /api/v1/voices](./endpoints/api/v1/voices/get)   | A `data` array of public TTS voices.                           |
| [GET /api/v1/models](./endpoints/api/v1/models/get)   | A `data` array of model IDs, input limits, and output formats. |
| [GET /api/v1/billing](./endpoints/billing)            | Credit balance and latest purchase or credit top-up.           |
| [GET /api/v1/openapi](./endpoints/openapi)            | The OpenAPI 3.1 document.                                      |

## Quick Start

Speech requests can identify a voice by `voice` + `model`, or by `voiceId` from `GET /api/v1/voices`. Use `voiceId` when you want a stable ID or when a voice name exists for more than one model.

Optional generation parameters:

- `response_format` — WAV for Gemini, MP3 for Orpheus, and MP3 (default) or WAV for Grok.
- `style` — freeform delivery instructions for Gemini; ignored by other models.
- `seed` — integer passed to Gemini; ignored by other models.
- `temperature` (`0`–`2`) — sampling temperature for Gemini voices (`gpro`/`gpro31`/`gpro38`); higher is more expressive. Ignored by other models.
- `speed` (`0.7`–`1.5`) — speech speed multiplier for Grok (`xai`) voices, per the xAI TTS API. Ignored by other models.

See the [speech limits](../guides/api#speech-limits) before sending long inputs.
Unrecognized JSON properties or out-of-range values return `400 invalid_request`.

### curl

```bash
curl -X POST 'https://sexyvoice.ai/api/v1/speech' \
  -H "Authorization: Bearer ${SEXYVOICE_API_KEY}" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "gpro",
    "voice": "achernar",
    "input": "Hello from SexyVoice API",
    "style": "calm",
    "seed": 1234,
    "temperature": 1.2
  }'
```

### curl with `voiceId`

Replace `VOICE_ID_FROM_CATALOG` with an `id` from the voices endpoint.

```bash
curl -X POST 'https://sexyvoice.ai/api/v1/speech' \
  -H "Authorization: Bearer ${SEXYVOICE_API_KEY}" \
  -H 'Content-Type: application/json' \
  -d '{
    "voiceId": "VOICE_ID_FROM_CATALOG",
    "input": "Hello from SexyVoice API",
    "style": "calm"
  }'
```

Do not include `voice` or `model` when you pass `voiceId`; the API derives the model from the voice.

### TypeScript (gpro)

```ts
const response = await fetch("https://sexyvoice.ai/api/v1/speech", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.SEXYVOICE_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "gpro",
    voice: "achernar",
    input: "Hello from TypeScript",
    style: "happy",
    seed: 42,
    temperature: 1.2,
  }),
});

const requestId = response.headers.get("request-id");
const json = await response.json();
```

### Python (gpro)

```python
import os

import requests

API_KEY = os.environ['SEXYVOICE_API_KEY']

response = requests.post(
    'https://sexyvoice.ai/api/v1/speech',
    headers={
        'Authorization': f'Bearer {API_KEY}',
        'Content-Type': 'application/json',
    },
    json={
        'model': 'gpro',
        'voice': 'achernar',
        'input': 'Hello from Python',
        'style': 'warm',
        'seed': 42,
        'temperature': 1.2,
    },
    timeout=30,
)

request_id = response.headers.get('request-id')
print(request_id, response.status_code, response.json())
```
